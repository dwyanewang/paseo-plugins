# ntfy-notify

Paseo 本地插件：主 agent 完成、失败或等待批准时，发布一条 [ntfy](https://ntfy.sh/) 通知。手机上的 ntfy App
订阅同一个主题即可收到，没有 iLink 的"用户先说话"窗口，也不经过微信的邮件提醒。

## 配置

在 Paseo App 的 设置 → 插件 → ntfy-notify → ntfy 通知 里填写：

- 服务器地址：daemon 发布通知用的地址。ntfy 和 daemon 在同一台机器上时用 `http://127.0.0.1:2586`；
  手机通过公网映射订阅时，也不影响这里用本机地址。
- 主题：手机上订阅同一个主题。
- 访问令牌：有该主题发布权限的令牌（`tk_` 开头）。服务器不需要认证时留空。

服务器地址、主题和令牌都存在 daemon 的 `server.secrets`；令牌不会回传给客户端，也不进日志。
保存后点"发送测试通知"确认。

## 通知规则

只看主 agent，子 agent 不单独通知：

- **完成**：每一轮正常结束都发，不论多短。如果它派出的子 agent 或提供方的后台任务还在跑，就等到后台结束再发。
  等待过程由 agent 和工作区的实时更新驱动；后台结束后再等 30 秒，确认 agent 没有被唤醒接着干活。
- **失败**：立即发，附错误。Claude Code 撞上用量限额时以正常完成结束、回复只有限额提示，
  这种轮次也按失败上报。
- **等待批准**：权限请求 20 秒内没人处理时发，附要执行的命令或要改的 diff。
- 取消的一轮不发，也会撤回这个 agent 还没发出去的通知。5 秒内的多条合成一条。
- 某个 Paseo App 在前台、并且 3 分钟内有过操作时跳过。

优先级：完成为 3（默认提示音）；失败和等待批准为 4（横幅加长振动）；插件启动通知为 2（静音）。

通知标题以结果开头，比如"✅ 完成 · 登录修复 · 38 秒"。正文是纯文本，包括摘要、agent 标题、工作区改动行数、
本轮指令、agent 最后的回复、改动的文件和命令统计。ntfy 会把超过 4,096 字节的消息转成附件，
所以正文各部分都有长度上限，整体再截到 4,000 字节以内。Android App 目前不渲染 Markdown，所以正文不用 Markdown。

## 手机端

1. 从 F-Droid 或 GitHub Releases 安装 ntfy Android App。这两个版本不依赖 Google 服务；
   订阅自建服务器时，Play 版也不走 FCM。
2. 添加订阅：填服务器的公网地址和主题，用只有读权限的账号登录。
3. 在 App 设置里保持"即时送达"开启。这会显示一条常驻通知，用来维持和服务器的连接。
4. 国产系统上要允许自启动、把省电策略设为无限制，并在最近任务里锁住 App，否则后台连接会被杀掉。

## 开发

```bash
npm run typecheck
npm test
paseo plugin install /absolute/path/to/ntfy-notify
```

依赖通过 `node_modules` 里指向 `../paseo` 的软链接提供；Zod 必须和宿主是同一份（4.4.3），
否则 `defineRpc` 的类型比对会让 tsc 内存溢出。插件没有运行时依赖。
